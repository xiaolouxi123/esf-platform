## 6. 版本与发布机制

**唯一来源**：`esf-launcher/package.json` → `0.6.1`。发版时 `release.ps1` 自动调用 `update-releases.js` + `sync-versions.cjs` + `check-versions.cjs`。

- 静态官网不请求 `/api/config`，改读同目录 `website/version.json`（早期硬编码 0.4.7 导致 Pages 永久显示旧版的事故已修）
- 更新记录展示 `releases.json` **全部 25 个历史版本 + 当前版本**
- `release.yml`：tag `vX.Y.Z` 触发；校验 tag 格式、缺产物即失败、**把全部历史 blockmap 带到新 Release**
- 插件发布**必须升 `BUILD`**，否则 114 的 updater 按版本比对不会拉取

**当前更新源快照**（只读探测确认）：`C:\esf\updates` 有 0.4.7~0.6.1 共 18 个历史版本 exe+blockmap，`latest.yml` 指向 0.6.1。客户端「历史版本 + 目前版本」已齐备，因此**决定不打客户端新 tag**。

## 11. 必须知道的坑

1. **KB 优先**：`AGENTS.md` 要求背景/历史/线上现状先读 `docs/kb/`；改了关键数字要回写，被取代的旧数字直接删掉，不要留着。
2. **凭据只记位置**，密码/密钥/邀请码不进仓库（含 KB）。仓库是 public。
3. **远程 PowerShell 脚本 ASCII-only**（PS 5.1 按 ANSI 读 UTF-8 会吞中文）；中文用 base64 传参。UTF-8 源码（`.sma` 等）只用编辑器工具改，不要用 PowerShell 文本管道。
4. **AMXX 必须 UTF-8 无 BOM 直编**；转 GBK 会让客户端/控制台中文乱码（`known-issues` 第 1 条）。
5. **本执行环境会清理命令派生的子进程树**：`npm run db:start` 拉起的 mysqld 会被杀，需作为受管后台任务直接运行（参数见 `server/scripts/dev-db.cjs`）。
6. **删除保护**：产物目录在 Desktop 下，`Remove-Item` 会被拦；构建脚本改为 amxxpc 覆盖 + 时间戳校验 / 换输出目录。
7. **114 只有 RDP**；其队列代理活在交互会话里，断开 RDP 就死。
8. `schtasks /end` 不会杀 node，要按 3000 端口杀进程后再 `schtasks /run /tn ESFAPI`。
9. 不要在没有真机验证的情况下把插件修复直接推生产（本次是在用户明确授权后上传的，仍留了验证清单）。
