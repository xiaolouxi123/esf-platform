# 约战大厅容量评估与玩家自建服务器方案

> 版本基线：0.6.61（2026-11-22）
> 结论先行：短期不要继续加平台免费服；先做「社区服接入（BYOS）」，把平台变成控制面，把游戏流量留给服务器所有者。玩家本机开服 + 内网穿透作为二期实验，不作为默认方案。

## 1. 现在到底能承载多少约战

| 资源 | 数量 | 约束 |
| --- | --- | --- |
| 平台登记服务器 | 4 台 | 217 两台 EVM、114 两台 FCX |
| 约战服 `is_challenge=1` | 2 台 | EVM 单挑房 #2 / #3 |
| 每台约战服同时进行的房间 | 1 个 | `startRoom` 会拒绝同服第二场 waiting/live |
| 单房人数 | 1v1=2，2v2=4 | 房间上限 4 人 |
| 单房观战 | 4 人 | `SPECTATOR_LIMIT=4` |
| 同时约战人数 | 最多 8 人 | 2 房 × 4 人 |
| 同时观战人数 | 最多 8 人 | 2 房 × 4 人 |
| 排位比赛服 | 1 台 | 114 fcx-1v1-1，和约战分开 |

所以当前不是「约战大厅 UI 不够」，而是**数据面只有两台可开房服务器，每台一次只能跑一场**。24 人在线时，最多 8 人进房，其余只能等或看。这个容量无法靠前端优化解决。

## 2. 为什么不能靠平台加服解决

- GoldSrc/HLDS 一场比赛需要一个独立服务端进程；一台 4GB VPS 实际能跑 4–6 个轻量 HLDS，但同时要留 API、MySQL、更新目录和带宽。
- 217 当前是 4GB 内存、约 12Mbps 出口，已经跑 API、Caddy、两台 EVM 和更新分发；再加房间会直接抢带宽和 CPU。
- 一台能稳定跑 HLDS 的 Windows VPS，按国内厂商常见价格约 ¥80–200/月；10 个并发房间就是 10 台或一台高配多实例，月成本 ¥300–1000+，且空闲时照样付费。
- 免费房间还会带来「开房不玩」「占房等人」「恶意锁服」等运营问题，成本不只是机器。

## 3. 五条路线对比

| 路线 | 平台成本 | 玩家门槛 | 可扩展性 | 排位可信度 | 工作量 | 建议 |
| --- | --- | --- | --- | --- | --- | --- |
| A. 社区服接入（BYOS） | 几乎为 0，只做控制面 | 服主装插件、填地址；玩家无感 | 高，有多少服主就有多少房 | 约战可，排位需白名单 | 5–6 人日 | **先做** |
| B. 玩家本机开服 + 直连 | 0 | 高：公网 IP/端口映射/防火墙 | 中，受 NAT 限制 | 低，房主可作弊 | 1–2 周 | 二期实验 |
| C. 平台加专用房间池 | ¥200–300/月起 | 低 | 中，一台 8GB 约 4–6 房 | 高 | 2–3 天运维 | 供给不足时补 |
| D. 本机开服 + 中继/虚拟局域网 | 中， relay 流量费 | 高 | 中 | 低 | 2–4 周 | 暂不做 |
| E. 服主市场/分时租赁 | 低，抽成 | 中 | 高 | 可分级 | 在 A 之上迭代 | 长期 |

## 4. 推荐方案：社区服接入（BYOS）

### 4.1 角色

- **平台**：房间大厅、身份 token、A2S 状态、房间规则、举报/封禁、版本校验。
- **服主**：提供 HLDS + AMXX 插件 + 公网 IP:端口，自己承担机器和带宽。
- **玩家**：在平台开房/加入，启动器仍然只负责写 token、拉起游戏、连接 IP:端口。

平台不转发游戏流量，只做「这间房用哪台服、谁有资格进、什么时候开」的控制面。

### 4.2 接入流程

1. 服主在启动器「我的服务器」填 IP:端口、展示名、最大人数。
2. 平台生成 6 位认领码，写入该服的 `amxx/configs/esf.conf`。
3. 服主重启地图或执行 `esf_claim <code>`；插件带 server_key + 认领码回调平台。
4. 平台同时做三件事：
   - A2S 查询 IP:端口，确认服务器真实在线；
   - 校验插件心跳/版本；
   - 记录 `owner_id`、`verified_at`、`last_seen_at`。
5. 服主设置开放时段、地图池、可承办模式（先只开约战/休闲）、是否私密房。
6. 玩家建房时，服务器下拉只显示「已验证 + 在线 + 当前时段开放 + 未锁服」的社区服；地图继续跟随 A2S 当前地图。

### 4.3 数据模型（最小改动）

在 `servers` 上补列，不新建一套服务器表：

```sql
ALTER TABLE servers
  ADD COLUMN owner_id BIGINT UNSIGNED NULL,
  ADD COLUMN host_type ENUM('platform','community','byo') NOT NULL DEFAULT 'platform',
  ADD COLUMN claim_status ENUM('unclaimed','pending','verified','revoked') NOT NULL DEFAULT 'unclaimed',
  ADD COLUMN claim_token_hash VARCHAR(255) NULL,
  ADD COLUMN allow_challenge TINYINT(1) NOT NULL DEFAULT 0,
  ADD COLUMN allow_ranked TINYINT(1) NOT NULL DEFAULT 0,
  ADD COLUMN max_concurrent_rooms TINYINT UNSIGNED NOT NULL DEFAULT 1,
  ADD COLUMN open_schedule VARCHAR(128) NULL,
  ADD COLUMN verified_at DATETIME NULL,
  ADD COLUMN last_seen_at DATETIME NULL;
```

房间表沿用 `challenge_rooms.server_key`，不需要改客户端连接协议。

### 4.4 信任分级

| 等级 | 能做什么 | 条件 |
| --- | --- | --- |
| community | 约战、休闲、私密房 | A2S 在线 + 插件心跳 + 认领码 |
| trusted | 可承办平台活动/排位 | 人工审核、固定插件版本、日志回传、至少 7 天稳定 |
| platform | 官方排位/官方约战 | 现有 217/114 机器 |

**排位绝不能由房主上报结果**。房主是 untrusted，改一个 AMXX 就能刷分；排位只跑官方/trusted 服，或由平台侧独立校验。

### 4.5 经济与治理

- 接入免费，服主自付机器；平台不补贴带宽。
- 可选「房费/打赏」：玩家用金币开房，平台抽 10–20%，服主得剩余；先不做，等供给起来再加。
- 服主每周最多开 N 场，防止一台服占满列表；平台可随时 revoke。
- 统一举报入口、共享黑名单、插件版本强制更新；过期插件不允许开房。
- 展示「社区服」标签，避免玩家误以为是官方服。

### 4.6 MVP 范围（建议 5–6 人日）

1. 迁移 + 管理台「服务器认领/审核/撤销」。
2. 启动器「我的服务器」页：填地址、认领码、开放时段、地图池、模式开关。
3. 后端 claim API + 插件 `esf_claim` + 心跳字段。
4. 约战建房过滤社区服；A2S 地图继续跟随；开赛锁服沿用现有逻辑。
5. 服务器详情/列表加「社区服」标签、服主昵称、举报入口。
6. 接入文档 + 一键插件包 + 排障清单。

不做：本机开服、NAT 穿透、中继、排位社区服、付费分账。

## 5. 玩家本机开服（二期实验）

### 5.1 需要什么

- 玩家机器上要有 `hlds.exe` 或可用的专用服务端；社区整合包通常只有客户端，需要额外分发 ~100MB 服务端。
- 公网可达：公网 IP + 端口映射，或 UPnP/NAT-PMP；国内家宽大量 CGNAT，失败率高。
- 防火墙放行 UDP 27015；启动器要检测端口可达性。
- 平台要发房间 token，插件校验；房主退出/断网要自动关房。

### 5.2 中继成本估算

GoldSrc 每玩家实际游戏流量按 3–8 KB/s 估：

- 4 人房：12–32 KB/s；
- 10 个并发房：120–320 KB/s，约 1–2.5 Mbps；
- 24 小时不间断 10 房：约 0.5–1.4 TB/月；
- 每天只开 4 小时：约 80–230 GB/月。

这还只是流量，不含中继 VPS、TURN 状态维护、DDoS 防护和排障。对现在的社区规模，投入产出比不如 BYOS。

### 5.3 结论

本机开服可以作为「高级服主」实验功能，但不能作为免费房间的默认方案；默认方案必须是 BYOS。

## 6. 什么时候加平台专用房间池

满足任一条件再考虑：

- 已验证社区服 `online` 且 `allow_challenge=1` 的数量连续 7 天 < 3；
- 约战等待时长 p90 > 3 分钟；
- 每天因「无可用服务器」失败的开房 > 20 次；
- 有活动/赛事需要固定机器。

补一台 8GB / 20Mbps 房间宿主机，跑 4–6 个 HLDS 实例，成本约 ¥200–300/月；比继续在 217 上挤更稳。

## 7. 建议的推进顺序

1. **现在**：0.6.61 已发布；约战保持 2 台免费服，加「无房提示 + 候场」引导，不追加机器。
2. **下一步（P1）**：BYOS MVP，5–6 人日；先找 2–3 个愿意接入的服主试点。
3. **观察 2 周**：统计社区服在线率、开房成功率、等待时长、举报量。
4. **再决定**：供给不足加专用房间池（C）；有明确公网服主需求再做本机开服（B）。
5. **长期**：服主市场/分时租赁（E），平台抽成覆盖控制面成本。

## 8. 需要产品拍板的三件事

1. 社区服是否允许开「约战」但不允许「排位」？（建议：允许约战，排位只给 trusted）
2. 社区服展示优先级：官方服优先，还是按延迟/空位排序？（建议：官方标签 + 综合排序，不隐藏社区服）
3. 是否做金币房费/服主分成？（建议：MVP 不做，先验证供给）
