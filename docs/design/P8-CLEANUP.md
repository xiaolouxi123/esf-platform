# P8 · 收口

一句话：**P0–P7 的覆盖段已经七层，第一次真正的清理不是合并，而是先把「再也不会被渲染的规则」删掉。** 这一步删了 80 条规则 / 356 行，页面一个像素没变。

## 改了三个地方

- **删死规则**：被重写页面淘汰的类（`.asset-card`、`.hall-stats`、`.challenge-grid`、`.admin-cards`、`.hero-side` 等）连同它们的 80 条规则一起删除，`App.css` 从 243.7KB 降到 235.7KB
- **脚本化判定**：`scripts/strip-dead-css.cjs` 先扫 `src/**` 的 JSX 里有没有这个类名，再决定是否整块删除；只有选择器里**所有**类都死才动手，`@media` 里的同名规则一起走
- **不改布局**：这次不动任何存活规则，所以大厅、排位、约战、服务器、资源库、管理台、设置、登录八个界面逐页截图对照，全都没有变化

## 为什么这样改

1. **先删再合，风险最小。** 合并两套同名规则需要人读 CSS 判断哪条是「最终值」；删死规则只需要证明「这个类不再出现在 JSX 里」，可以被脚本验证。
2. **死规则会误导后来人。** `.asset-card` 有六条规则、跨三处媒体查询，现在一个都用不上；留着只会让人以为资源库还是卡片网格。
3. **控制改动面。** 这一轮不碰存活规则，出问题时回滚一个文件即可；合并覆盖段留到下一轮单独做。
4. **脚本比手删可靠。** 判定条件（类名在 `src/**` 里不再出现、选择器内所有类都死）写死在脚本里，下次再重写页面直接跑一遍。

## 代码落点

| 文件 | 改动 |
| --- | --- |
| `src/App.css` | 删除 80 条死规则、356 行；存活的 P2–P7 覆盖段一行没动 |
| `scripts/strip-dead-css.cjs` | 新增：扫描 `src/**` 的类名使用情况，按 DEAD 白名单整块删除规则，带 `--write` 开关 |

**可以看到的东西**：八个界面逐页截图与清理前一致；`git diff` 只删不加（356 行全部是删除）。
