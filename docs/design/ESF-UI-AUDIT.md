# ESF 平台界面审计与改版方案

> 范围：启动器全部界面（大厅、排位、约战、服务器、军备库、管理台、频道、设置）+ 常驻面板 + 弹窗体系。
> 依据：`esf-launcher/src` 全量代码与 `App.css` 实测统计，不含服务端后台页面。

## 一句话结论

**ESF 的界面不是"不好看"，而是从来没有过设计系统：7,265 行 CSS 里塞了 110 种颜色、37 档字号、27 种圆角、5 套弹窗实现。**

改版的重点不是换皮，而是先把"决定"变成 token，再把页面收进同一套组件。

## 一、现状盘点

界面共 7 个页面、4 个常驻浮层、3 个结果类弹窗，全部由一个 164 KB 的 `App.css` 承载，没有设计文档。

| 区块 | 代码规模 | 主要内容 |
|---|---|---|
| 大厅 Lobby | 54.2 KB | 地图 rail、开始游戏、在线房间、平台公告、最近上架、更新进度 |
| 排位 RankedPage | 26.0 KB | 段位进度、匹配席位、对局卡、我的战绩、排队态 |
| 约战 ChallengePage | 26.8 KB | 房间卡、席位、邀请条、结算弹窗、建房表单 |
| 服务器 ServerHall | 24.8 KB | 服务器探测、公开列表、自定义服务器表单 |
| 军备库 AssetLibrary | 12.2 KB | 上传面板、资源卡网格、筛选 |
| 管理台 AdminPanel | 46.8 KB | 概览卡、用户/资源/称号表格、平台设置 |
| 频道/聊天 ChatPanel | 5.3 KB | 频道欢迎、消息列表、输入框 |

常驻部分：标题栏 2.9 KB、成员侧栏 19.9 KB、在线面板 8.0 KB、设置抽屉 19.0 KB。

### 硬数字

- **110** 种不同的十六进制颜色，**532** 处 `rgba()` 直接写死
- **37** 档字号，从 8.5px 到 52px，相邻档常常只差 0.5px
- **27** 种 `border-radius`，其中 1px、3px、4px、5px、6px、7px 同时存在
- **49** 条 `box-shadow`，没有 elevation 层级概念
- **16** 个与弹窗相关的类名：`challenge-modal*`、`challenge-result-modal`、`ranked-result-modal`、`update-modal*`、`member-profile*`

## 二、六个结构性问题

### 1. 颜色没有约束，品牌色被稀释

橙色 `#ff8a1f` 是唯一的行动色，但页面里同时存在 110 种颜色：相近的深蓝底有五六种写法，成功/失败各有三四档绿红。结果是"哪里都在发光"，真正的按钮反而不突出。

### 2. 字号失控，层级读不出来

37 档字号里，10px 与 10.5px、11px 与 11.5px 这种半像素差在同一屏里出现，读者感知不到层级，只觉得"文字大小很乱"。正文与说明文字的最低字号到了 8.5px。

### 3. 圆角与阴影各自为政

27 种圆角意味着两张卡片放在一起时边缘对不齐；49 条阴影没有 hover/active 的递进关系。卡片、面板、弹窗看起来"各是各的"。

### 4. 弹窗有五套实现

挑战结算、排位结算、更新提示、成员资料卡、头像灯箱各写一套，关闭按钮位置、内边距、底部按钮排布都不一样。同样是"结果"，两种结算弹窗的视觉语言完全不同。

### 5. 页面骨架重复

大厅、服务器、军备库、管理台各自写了一套"页头 + 筛选 + 列表/网格"结构，类名不同、间距不同、空态文案不同，改一处要改四处。

### 6. 没有设计文档

`docs/` 下只有功能与运维文档，没有一份说明颜色、字号、间距该怎么用。新人（或下一次改版）只能继续抄上一页的写法，问题会复利。

## 三、五条设计原则

**先删，再加。能用已有组件表达的需求，不再新建类名。**

1. **深色舞台，橙色只给行动。** 背景只有三层，橙色只出现在主按钮、当前选中、进度与关键数字上。
2. **一套组件，多页复用。** 卡片、列表行、表格、表单、弹窗、徽章各只有一种实现。
3. **信息分三层。** 主信息 15–18px 高对比，次信息 13px 中对比，弱信息 11–12px 低对比，只此三档。
4. **动效只做状态反馈。** 120ms 与 200ms 两档，只动 opacity 与 transform，不做装饰性动画。
5. **每加一个样式，先问能不能用已有的。** 新增色值/字号/圆角必须在 token 表里存在。

## 四、设计系统 v1

### 颜色

| 角色 | 值 | 用途 |
|---|---|---|
| bg/base | `#0B0E14` | 窗口底 |
| bg/raised | `#121722` | 面板、侧栏 |
| bg/float | `#1A2130` | 卡片、弹窗 |
| line/subtle | `rgba(255,255,255,.07)` | 分隔线 |
| line/strong | `rgba(255,255,255,.14)` | 卡片描边 |
| text/primary | `#EEF1F7` | 标题、正文 |
| text/secondary | `#A4ADC2` | 说明 |
| text/tertiary | `#7A8399` | 时间、路径、元信息 |
| brand | `#FF8A1F` | 主按钮、选中、进度 |
| brand/hover | `#FF9E45` | 悬停 |
| success / danger / warn / info | `#3DDC97` / `#FF5F6D` / `#FFC861` / `#3FD0FF` | 语义色，各只一档 |

颜色总数从 110 收敛到 **22**（含 4 个语义色的浅色变体）。

### 字号与字重

| Token | 值 | 用途 |
|---|---|---|
| display | 32px / 700 | 页面主标题 |
| h1 | 24px / 650 | 区块标题 |
| h2 | 18px / 600 | 卡片标题 |
| body | 15px / 450 | 正文 |
| label | 13px / 500 | 表单标签、列表主信息 |
| caption | 12px / 450 | 辅助说明 |
| micro | 11px / 500 | 徽章、表格表头（大写 + 字距 0.08em） |
| mono | 12px / 450 | 路径、版本号、IP |

37 档收敛到 **8** 档；正文不低于 12px。

### 间距、圆角、阴影、动效

间距以 4px 为基：4 / 8 / 12 / 16 / 24 / 32 / 48。圆角只留四档：6（徽章）/ 10（控件）/ 16（卡片与弹窗）/ 999（胶囊）。阴影三档：card、hover、modal。动效两档：120ms（hover/按压）、200ms（抽屉/弹窗）。

### 组件收敛

| 现状 | 收敛为 |
|---|---|
| 5 套弹窗实现 | 1 套 Modal：头部标题+关闭、可滚动内容、底部主次按钮 |
| 4 套"页头+筛选" | 1 套 PageHeader + 1 套 FilterBar |
| 3 套表格 | 1 套 DataTable（44px 行高、11px 大写表头、统一空态） |
| 2 套历史行 | 1 套 ListRow（左主体 / 右数值） |
| 3 套徽章 | 1 套 Badge（4 种语义色） |

## 五、页面级调整

1. **大厅**：主次拉清楚。地图与"开始游戏"占主列，公告与最近上架进右列；在线房间数从标题里挪到统计条；更新进度条统一成全局组件。
2. **排位**：段位进度、匹配席位、我的战绩共用一套卡片；结算弹窗并入统一 Modal，历史态与实况态只差底部按钮。
3. **约战**：房间卡把"席位"抽成独立组件，状态徽章统一；建房表单与设置抽屉共用字段组件。
4. **服务器**：列表行改成四列网格（名称 / 地址 / 模式 / 状态），自定义服务器表单与探测结果分区。
5. **军备库**：资源卡固定三段式（封面 / 名称+版本 / 描述+操作），筛选用统一 FilterBar。
6. **管理台**：三张表统一 DataTable，概览卡与用户卡共用 Card；称号、设置表单共用字段。
7. **设置抽屉与频道**：字段、开关、路径块统一；聊天消息行固定"头像 / 名字+时间 / 正文"三段。

## 六、三阶段落地

1. **P0 · 一天**：建 token 层与六个基础组件（Button / Card / Badge / Input / Modal / ListRow），只替换颜色、字号、圆角、阴影，不改布局。
2. **P1 · 三天**：大厅、排位、约战、服务器四页改用新组件；删除对应旧样式。
3. **P2 · 两天**：军备库、管理台、频道、设置抽屉收口；清理剩余孤立类名。
4. **P3 · 一天**：动效、空态、加载态、错误态统一，截图回归。

### 验收清单

- [ ] 颜色 token 之外的颜色值为 0
- [ ] 字号只用 8 档，最小 11px（徽章）与 12px（正文辅助）
- [ ] `border-radius` 只用 4 档
- [ ] 弹窗只有 1 个实现类
- [ ] `App.css` 行数下降 30% 以上
- [ ] 七个页面截图与改版前逐页对照，信息不缺失

## 七、这一轮不做的事

不改信息架构与路由，不动任何业务逻辑与接口，不做浅色主题，不引入 UI 框架或图标库替换，不在本轮重画全部图标。改版以"可回滚的样式层重构"为边界。
