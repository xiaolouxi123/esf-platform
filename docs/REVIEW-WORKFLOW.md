# 审核与发布流程（硬规则）

> 生效：2026-11-18。发布 = 打 tag + 部署 217 + 玩家收到更新。**任何版本、任何板块，都必须先由用户在桌面审核版里实际点过并明确同意，才能发布。**
> 这条闸门已写进 `scripts/release.ps1`：不带 `-Approved` 直接抛错退出。

---

## 1. 我（开发者）每次改完必须做的

1. 自测：`npx.cmd eslint .`、`npm.cmd test`、`npm.cmd run build` 全绿；涉及界面的改动补截图/自动化点击。
2. 产出桌面审核版：`cd esf-launcher && npm.cmd run review:build`（约 5 秒，不跑 electron-builder）。
   - 做法：直接复制 `node_modules\electron\dist` + 源码目录到审核目录，`resources\app\` 是解包状态，不是 asar。
   - 为什么不用 electron-builder：本机 `electron-builder --dir` 的 packaging 阶段会卡死（0 文件产出、无 7z 子进程），与审核版无关；正式安装包仍由 release.ps1 走 CI 构建，不受影响。
   - 产物：`桌面\ESF平台-审核版\`（绿色目录，不改注册表、不动正式安装目录）
   - 快捷方式：`桌面\ESF 平台 - 审核版.lnk`，参数 `--review-build`
   - 独立 profile：`%APPDATA%\esf-launcher-review`（和正式版、开发测试互不干扰）
   - 连正式后端、**不参与自更新**（避免审核目录被正式更新覆盖）
3. 在回复里写清：这一版改了什么、看哪几个页面、旧问题哪条被修掉、还剩什么。
4. **等用户审核**。用户说「可以发」之前，不改版本号、不打 tag、不部署。

## 2. 用户审核方式（任选）

- **桌面试用版**：双击 `ESF 平台 - 审核版`，就是打包后的真实体验（和玩家拿到的一致）。
  - 注意：审核版启动参数是 `--review-build`；如果在已设置 `ELECTRON_RUN_AS_NODE=1` 的终端里手动起，会报 `bad option`，双击快捷方式不受影响。
- **源码热更**：`cd esf-launcher && npm.cmd run dev`（正式后端）或 `npm.cmd run dev:test`（本机 3000 + 独立 profile），Vite 热更新，改完刷新即可看。
- 不登录也能看大厅/排位/服务器；要测排位、约战、资源库安装，用测试账号（用完删）。

## 3. 审核通过后我才做

1. 按 0.6.5x 递增版本号（`0.6.54` → `0.6.55` …），写 CHANGELOG + releases.json。
2. `scripts\release.ps1 -Version 0.6.54 -Notes "..." -Approved`（中文 Notes 必须 UTF-8 BOM 包装）。
3. 等 GitHub Actions 出包 → 校验 sha512 → 部署 217 → 验证两台 `/api/config` latestVersion。

## 4. 审核清单（每次照抄，逐条打勾）

- [ ] 1366×768 下整页可见、状态栏贴底、无竖向滚动
- [ ] 大厅主按钮 = 快速匹配；本地对局从三处入口都能打开同一弹层
- [ ] 匹配中 → 已找到 → 已准备 → 结算 → 下一场/本轮结束 全流程可走
- [ ] BO3 第 3 场结束不再自动续排
- [ ] 插件中心 4 行插件表有数据（不是 0/4 空态）
- [ ] 频道可发送、标签可筛选
- [ ] 地图抽屉可搜索/收藏，底部「本地开图」可用
- [ ] 设置抽屉 8 分区可展开，保存生效
- [ ] 服务器列表房名以管理台为准，延迟/人数实时
- [ ] 更新提示不再指向错误版本（审核版本身不检查更新）

## 5. 版本号规则（用户已确认）

- 0.6.51 → 0.6.52 → 0.6.53 → 0.6.54 … 每版 +1，不做语义化大跳。
- 版本号只在审核通过后才改；审核版目录名不带版本号，避免「桌面堆一堆测试版」。
